# 5. Shared-UI-library contract and CLI UX standard, from the fleet UX audit

- **Status:** Proposed
- **Date:** 2026-07-19
- **Deciders:** Anthony Gréau
- **Pillars touched:** none
- **Supersedes / Superseded by:** —

## Context

An exhaustive UX/accessibility audit of the fleet (2026-07 — 33 interface-bearing
repos, 783 real screens enumerated from code, 754 findings) re-clustered the findings
by propagating root cause. The result: the debt is **not 754 independent per-repo bugs**
but ~9 systemic levers, two of which are gaps in the standards themselves.

- **~487 of 754 findings (65 %) route through a single repo, `chrysa-lib` (`@chrysa/ui`).**
  The shared library ships class names but **no CSS and no design tokens**
  (`package.json` has no `style`/`exports`/`sideEffects`; zero `.css` in the package).
  So `:focus-visible`, WCAG 2.1 AA contrast, ≥44px targets, `prefers-reduced-motion`
  and dark/light are **re-invented by every consumer** — which is exactly why the audit
  found the same defects in all 31 consuming apps. `Input` makes a11y optional
  (label optional, no `aria-invalid`/`aria-describedby`); `BackendConnectionBanner` is
  shipped complete but **mounted nowhere** in ~5 repos.
- **CLI is an un-normed surface — 104 findings.** `STANDARDS.chrysa.md` had no CLI
  clause, so distributed CLIs diverge: missing `--version`, `--dry-run` that writes
  (measured: `guardian --baseline --dry-run` wrote 145 759 bytes and rebuilt the AIDE
  baseline), machine output on stderr, undocumented exit codes.

The existing WCAG/dark-mode/i18n non-negotiables already stated the *intent*; they were
not enforced because the shared substrate did not guarantee them and the CLI surface was
unmentioned.

## Decision

Add two sections to `standards/STANDARDS.chrysa.md`:

1. **Shared UI library contract** — `@chrysa/ui` guarantees (not suggests): ships its own
   CSS + tokens (AA, focus-visible, ≥44px, reduced-motion, dark/light out of the box);
   owns `loading`/`empty`/`error` states and mounts `BackendConnectionBanner`; makes a11y
   mandatory by type on interactive primitives.
2. **CLI UX** — every distributed CLI exposes `--version`/`--help` with examples,
   `stdout`=data / `stderr`=logs, `--json` on stdout, documented exit codes, TTY/`NO_COLOR`
   colour, a truly non-destructive `--dry-run` (test-verified) and a non-interactive CI flag,
   and actionable errors.

## Fatal hypothesis

The dominant UX debt is **substrate-level**: fixing `@chrysa/ui` (styles + states + a11y)
and adding a CLI norm removes the recurring cause, rather than the findings being genuinely
independent per-repo bugs that a shared fix cannot address.

## Kill-test

Once the `@chrysa/ui` contract ships, run `axe-core` at WCAG 2.1 AA on **three** consumer
apps (chrysa-portfolio-viz, devtool, sport-intelligence-hub) built with **no local style
overrides**. Threshold: **0 contrast / focus-visible / target-size violations** attributable
to shared primitives. Checked at the first consumer bump after the contract release. **On
breach** (any such violation persists), the hypothesis is false — the debt is not
substrate-level — and this ADR is `Killed`; revert to per-repo remediation.

## Validation gate

Merge the standard only once `@chrysa/ui` has a released version that (a) exports a stylesheet
consumed with a single import and (b) passes its own axe-core AA scan in CI. Until then the
two sections ship as **stated intent with ADR reference**, not as an enforced gate.

## Options considered

| Option | Why not |
| ------ | ------- |
| Fix each of the 31 apps independently | 487 findings re-appear on the next feature; treats symptoms, not the shared cause. |
| Only restate WCAG/AA louder | The intent already existed and was not met; a statement without a substrate guarantee changes nothing. |
| Leave CLI unspecified | 104 findings on a surface with no rule; `--dry-run` that writes is a security-grade defect (IDS re-baseline). |

## Consequences

- **Accepted cost:** `@chrysa/ui` must ship and maintain a stylesheet + tokens and tighten
  its component API (breaking for consumers that pass a11y-optional props) — a deliberate
  breaking change, versioned via GitVersion.
- **Gain:** one substrate fix closes ~487 findings across 27 repos; new repos inherit AA +
  states + a11y for free.
- **Debt created:** the CLI norm needs a shared `base-cli` helper (argparse/click wrapper)
  to avoid re-implementation per repo — follow-up, owner TBD.
- **Blast radius if Killed:** revert both sections; audit remediation falls back to the
  per-repo prompt already generated by the audit artifact.
