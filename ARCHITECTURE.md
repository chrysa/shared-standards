# Architecture — shared-standards

> Project-level meta-doc. Describes **how this repository works as a project**: what it
> produces, how the pieces fit, and where the moving parts live. It does **not** restate
> or edit the standards canon. The canon is the source of truth for *rules*; this file is
> a map of the *machinery* around them.
>
> Tags: **FACT** = verified from repo files; **INFERENCE** = reasoned from structure;
> **UNKNOWN** = not determinable from the repo alone. Evidence pointers are given inline.

---

## 1. What this repo is

**FACT.** `shared-standards` is the chrysa ecosystem's canonical standards, doctrine, and
Claude Code DevEx tooling repository. It ships: the standards canon, generated per-agent
views, GitHub Copilot instruction templates, copy-to-use CI/workflow templates, bootstrap
templates, Claude Code hooks/skills/rules, and the fleet-wide audit/distribution scripts.
_Evidence: `README.md`, `standards/README.md`, `CLAUDE.md` (Repository Structure)._

**FACT.** It is a **documentation-and-tooling repo**, not an application. The `Makefile`
declares `dev`, `test`, `build`, `typecheck` as no-ops ("shared-standards is a
documentation repo") and `# makefile-tier: lib`. The only executable test surface is the
`console/` app plus the `scripts/` host-test suite. _Evidence: `Makefile`._

## 2. The core pipeline: canon → views → repos

The central mechanism is a one-way generation pipeline. Edit the canon; everything
downstream is regenerated and drift-checked — never hand-edited.

```
standards/STANDARDS.chrysa.md        (canon — the single source of truth, owner-only)
   │  classified by standards/rule-domains.yaml + standards/domains.yaml
   ▼
scripts/gen_agent_views.py  (make gen-agent-views)
   ├─► standards/CORE.chrysa.md          (GENERATED slim core)
   ├─► standards/rules/<domain>.md        (GENERATED per-domain detail, load-on-demand)
   ├─► CLAUDE.md  managed `chrysa:standards` block   (inlined slim core)
   ├─► AGENTS.md                          (GENERATED agent view)
   └─► .github/copilot-instructions.md    (GENERATED)
   │  kept byte-faithful by the `agent-views-drift` gate (pre-commit + CI)
   ▼
scripts/distribute-standards.sh          (fleet-wide distribution)
   └─► the managed `chrysa:standards` block in every consumer repo's CLAUDE.md
```

**FACT.** Views are generated by `scripts/gen_agent_views.py` and kept byte-faithful by an
`agent-views-drift` gate. `standards/CORE.chrysa.md`, `standards/rules/`, `AGENTS.md`, and
`.github/copilot-instructions.md` are all marked GENERATED. _Evidence: `standards/README.md`
lines 12-20, `Makefile` `gen-agent-views` target._

**FACT.** `scripts/distribute-standards.sh` is the canonical, idempotent way to push the
managed `chrysa:standards` block into consumer repos; `CLAUDE.md` carries an explicit
`managed by distribute-standards.sh · DO NOT EDIT` marker around that block.
_Evidence: `CLAUDE.md` lines 152/294, `scripts/distribute-standards.sh`._

**INFERENCE.** Editing the canon has fleet-wide blast radius (the `standards/README.md`
notes "Editing the socle changes 68 repos on the next `distribute-standards` run"). The
`standards-authoring` skill exists to govern such edits. _Evidence: `standards/README.md`
line 43; `dev-focus:standards-authoring` skill description._

## 3. Per-repo context files (ADR D-0012)

**FACT.** A second generator, `scripts/gen_context_files.py` (`make gen-context-files`),
produces this repo's own context files from its content: `handover.md`, `context-map.json`,
`llms-full.txt`, `ai-instructions.md`. Each is stamped `GENERATED … do not edit` and
verified by a `context-files-drift` gate. The `context-files-report` target is the ADR
D-0012 kill-test tally. _Evidence: `Makefile`, `handover.md` / `ai-instructions.md` headers._

## 4. Distributable assets (copy-to-use, not imported)

**FACT.** `workflows/` and `templates/` are **copy-to-use templates**, explicitly *not*
callable via `uses: chrysa/shared-standards/...`. Composite/reusable GitHub Actions live in
the separate `chrysa/github-actions` repo and are called from inside a copied workflow.
_Evidence: `README.md` lines 24, 78-82._

| Asset dir | Role (FACT) |
| --- | --- |
| `standards/` | The canon + generated views + taxonomy. Owner-only. |
| `copilot-instructions/` | Copilot instruction templates (`base.md` ecosystem-wide + per-stack). |
| `workflows/` | CI/workflow templates copied into a consumer's `.github/workflows/`. |
| `templates/` | Bootstrap file templates (CLAUDE.md, .gitignore, dependabot.yml, VS Code tasks, e2e scaffold, docs-structure). |
| `.claude/hooks/` | Claude Code DevEx hooks (secret-scanner, circuit-breaker, …). |
| `.claude/skills/` | Load-on-demand skill modules distributed to the fleet. |
| `.claude/rules/` | Cross-repo agent rules (`adr.md`, `pillars.md`, `folder-readme.md`). |
| `scripts/` | Fleet audit + apply + distribution automation. |
| `console/` | Small Python console app (the repo's only Docker-tested code). |

## 5. Enforcement & audit surface

**FACT.** The repo is both the author and an enforcer of fleet standards. `scripts/`
contains `apply-*`, `audit-*`, `check-*`, `setup-*`, and `sync-*` families that apply or
verify branch policy, CI process, docker/makefile/quality-gate conformance across the
`repos.yml`-listed fleet. Drift checks (`check-managed-drift.sh`, `check-canonical-drift.sh`,
`check_domains_drift.py`) protect the generated/managed surfaces. _Evidence: `scripts/` listing._

**FACT.** Local security/hygiene gates run in pre-commit and CI: `detect-secrets`
(`.secrets.baseline`, `workflows/secret-scan.yml`) and a custom PII scanner
(`scripts/pii_scan.py`, `.pii-allowlist.json`, `.pii-scan.toml`, `workflows/pii-scan.yml`),
plus a quality gate (`scripts/quality_gate.py`, `.quality-gate.json`). _Evidence: repo root
+ `workflows/` + `README.md` PII section._

## 6. Testing model

**FACT.** Two host-native + one containerised test surface:
- `make test-scripts` runs the `scripts/` and `pii/` test suites on the host with coverage
  (they are invoked by pre-commit without Docker, so their coverage must travel to Sonar).
- `make docker-test` builds `console/`'s dev image and runs its pytest suite in-container,
  emitting a repo-root `coverage.xml` with rewritten paths for SonarCloud.
- `make ci` = `lint typecheck test`. Root `make test` is intentionally a no-op.
_Evidence: `Makefile` (`test-scripts`, `docker-test`, `ci`, no-op targets), `conftest.py`._

**UNKNOWN.** Exact current coverage figures and Sonar quality-gate status are not
determinable from a static read (they depend on CI runs, not committed here).

## 7. Decision records

**FACT.** Two ADR layers coexist:
- `DECISIONS.md` — repository-local ADRs (`D-XXXX`) tracking any deviation from the chrysa
  canon. D-0001 states no active deviation is in effect.
- `docs/adr/` — the numbered ADR corpus (`0001…`, `D-0010…`) governing the standards and
  tooling themselves. The chrysa ADR format (fatal hypothesis / kill-test / validation gate)
  is defined in `.claude/rules/adr.md`.
_Evidence: `DECISIONS.md` header, `context-map.json` adr list, `.claude/rules/adr.md`._

## 8. Constraints that shape the repo (INFERENCE unless noted)

- **The canon is owner-only.** `standards/STANDARDS.chrysa.md`, `annexes/`, `domains.yaml`,
  `rule-domains.yaml`, `GOVERNANCE.md`, and every generated view are edited via the canon +
  regeneration, never by hand. **FACT** — stated in `standards/README.md`.
- **English on disk.** All committed files are English. **FACT** — `CONTRIBUTING.md`,
  `standards/README.md`. A `hookify.warn-french-in-files` local hook backs this.
- **Make-only dev loop.** Contributors call `make` targets, never `pytest`/`ruff`/`mypy`
  directly on the host. **FACT** — `CONTRIBUTING.md`.
- **`chrysa/standards` (singular) is deprecated/archived** — never add there. **FACT** —
  `standards/README.md` line 45.
